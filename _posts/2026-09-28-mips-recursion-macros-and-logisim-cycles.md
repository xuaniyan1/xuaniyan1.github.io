今天学的内容看起来分成两块：一块是 MIPS 的宏、递归和栈，另一块是 Logisim 的寄存器、周期和矩阵快速幂。但它们其实都在逼我回答同一个问题：**当前这一层、当前这一个周期，到底保存着什么；下一层或下一个周期回来以后，又有什么发生了变化？**

这篇先把今天真正用到的东西记下来。重点不是堆一份汇编模板，也不是再画一遍电路，而是留下我以后最容易忘记的状态变化。

## 一、输入输出宏：参数传进来的其实是寄存器

### 读入一个整数

```asm
.macro scanfint(%reg)
    li   $v0, 5
    syscall
    move %reg, $v0
.end_macro
```

使用：

```asm
scanfint($s0)
```

执行过程是：

```text
系统调用5读入整数
    ↓
结果放在$v0
    ↓
把$v0复制到传入的寄存器$s0
```

这里原来把参数写成 `%addr` 容易让我以为它是内存地址。实际上这个宏目前接收的是一个寄存器，所以叫 `%reg` 更准确。如果以后真要把输入存入内存地址，应该先读到 `$v0`，再使用 `sw`。

### 输出一个整数

```asm
.macro printfint(%reg)
    move $a0, %reg
    li   $v0, 1
    syscall
.end_macro
```

使用：

```asm
printfint($s0)
```

这里 `$a0` 是系统调用的参数，`$v0=1` 表示打印整数。

这两个宏的价值不是减少三行代码这么简单，而是给调用处一个清楚的含义：

```asm
scanfint($s0)
printfint($s0)
```

我看到调用就知道在做什么，不必每次重新解释 syscall 编号。

## 二、二维矩阵的偏移量：先确定一行实际占多少列

二维数组按行连续存储时：

```text
元素下标 = i * 每行实际列数 + j
字节偏移 = 元素下标 * 每个元素的字节数
```

假设元素是 32 位整数，每个元素占 4 字节。

### 每行有 8 列

如果一行实际占 8 个整数：

```text
offset = (i * 8 + j) * 4
       = ((i << 3) + j) << 2
```

对应宏：

```asm
.macro getoffset8(%ans, %i, %j)
    sll %ans, %i, 3      # %ans = i * 8
    add %ans, %ans, %j   # %ans = i * 8 + j
    sll %ans, %ans, 2    # %ans *= 4，得到字节偏移
.end_macro
```

### 逻辑上 9 列，但实际补齐为 16 列

如果矩阵逻辑上是 `6×9`，为了方便移位，把每一行实际空间补成 16 列，那么行跨度必须按 16 算：

```text
offset = (i * 16 + j) * 4
       = ((i << 4) + j) << 2
```

正确的宏应该是：

```asm
.macro getoffset16(%ans, %i, %j)
    sll %ans, %i, 4      # %ans = i * 16
    add %ans, %ans, %j   # %ans = i * 16 + j
    sll %ans, %ans, 2    # %ans *= 4
.end_macro
```

我原来一边说“补成 16 列”，一边在宏里写 `sll ...,3`，这两个说法是矛盾的。`<<3` 是乘 8，`<<4` 才是乘 16。

例如：

```asm
li $t5, 2
li $t6, 5
getoffset16($t7, $t5, $t6)
```

得到：

```text
(2 * 16 + 5) * 4 = 148字节
```

偏移量只是相对于矩阵首地址的距离。真正访问元素还需要：

```asm
la  $t0, matrix
add $t0, $t0, $t7
lw  $t1, 0($t0)
```

## 三、push 和 pop：保存的是当前这一层还要用的东西

```asm
.macro push(%reg)
    addi $sp, $sp, -4
    sw   %reg, 0($sp)
.end_macro

.macro pop(%reg)
    lw   %reg, 0($sp)
    addi $sp, $sp, 4
.end_macro
```

现在我对 `$ra` 的理解可以固定成一句话：

> 当前这一层需要的返回地址，就是进入这一层时压入栈中的那个；退出这一层时，再把同一个地址弹回 `$ra`。

但不是所有参数都必须压栈。每次准备执行 `jal` 时，只问：

> 等下一层回来以后，当前这一层还需要哪些旧值？

需要并且可能被下一层覆盖的值才保存。

常见寄存器可以这样理解：

| 寄存器       | 用途   | 什么时候由当前层保存           |
| --------- | ---- | -------------------- |
| `$ra`     | 返回地址 | 当前函数还要执行 `jal` 时通常保存 |
| `$a0-$a3` | 参数   | 递归返回后还要用旧参数时保存       |
| `$t0-$t9` | 临时值  | 跨过 `jal` 后仍要使用时保存    |
| `$s0-$s7` | 保留值  | 当前函数要修改时，应保存调用者的旧值   |
| `$v0-$v1` | 返回值  | 通常不要恢复旧值，否则会覆盖刚算出的答案 |
|           |      |                      |

栈是后进先出：

```asm
push($ra)
push($a0)

# ...

pop($a0)
pop($ra)
```

## 四、递归 GCD：下一层返回以后，答案已经在 `$v0`

```asm
.text
.globl main

main:
    li   $s0, 15
    li   $s1, 65
    move $a0, $s0
    move $a1, $s1

    jal  gcd

    move $a0, $v0
    li   $v0, 1
    syscall

    li   $v0, 10
    syscall

# gcd(a, b)
# 参数：$a0=a，$a1=b
# 返回：$v0=gcd(a,b)
gcd:
    push($ra)

    beq  $a1, $zero, gcd_base

    div  $a0, $a1
    move $a0, $a1
    mfhi $a1

    jal  gcd

    # 下一层已经把答案放入$v0，不要再用$a0覆盖它。
    j    gcd_return

gcd_base:
    move $v0, $a0

gcd_return:
    pop($ra)
    jr   $ra
```

调用过程：

```text
gcd(15,65)
gcd(65,15)
gcd(15,5)
gcd(5,0)
```

基本情况得到：

```text
$v0 = 5
```

外层不再修改 `$v0`，这个结果就会原样返回到 main。

在 `jal gcd` 后写：

```asm
move $v0, $a0
```

对这份程序碰巧仍然会得到 5，因为最深层留下的 `$a0` 也是 5。但调用约定只保证返回值在 `$v0`，不保证 `$a0` 仍然属于当前层。正确思路是相信子调用：

```text
调用前：参数放入$a0、$a1
调用后：答案从$v0取出
```

## 五、递归阶乘：为什么它需要额外保存 `$a0`

阶乘与 GCD 的区别是，递归返回以后还要使用当前层原来的 `n`：

```text
fact(n) = n * fact(n-1)
```

所以在修改 `$a0` 并调用下一层之前，必须保存当前层的 `$a0`。

```asm
# 参数：$a0=n
# 返回：$v0=n!
fact:
    push($ra)
    push($a0)

    beqz $a0, fact_base

    addi $a0, $a0, -1
    jal  fact

    # 恢复当前层原来的n。
    pop($a0)
    mul  $v0, $a0, $v0

    pop($ra)
    jr   $ra

fact_base:
    li   $v0, 1

    # 基本情况也必须保持push/pop平衡。
    pop($a0)
    pop($ra)
    jr   $ra
```

这里不能把 `$a0` 的恢复放在乘法之后，因为乘法正需要当前层原来的 `n`。

对比一下：

```text
GCD：子调用返回后，不再需要当前层旧参数，只保存$ra。
阶乘：子调用返回后，还要乘当前层的n，所以保存$ra和$a0。
```

这比背“递归要保存哪些寄存器”更可靠。

## 六、乘法和除法：结果不只有眼前这一半

### 1. 乘法为什么分高位和低位

两个 `n` 位数相乘，完整结果最多需要 `2n` 位。

例如两个 8 位无符号数：

```text
0x81 * 0x81 = 0x4101
```

完整结果是 16 位，可以拆成：

```text
高8位 = 0x41
低8位 = 0x01
```

如果只保留低 8 位，就只会看到 `0x01`，高位信息已经被截断。Logisim 乘法器将结果拆成低位输出和高位输出时，完整乘积应该理解为：

```text
完整结果 = {高位部分, 低位部分}
```

也就是高位放在前、低位放在后进行拼接。

在 MIPS 中，对应的是：

```asm
mult  $t0, $t1      # 有符号乘法
mflo  $t2           # 读取低32位
mfhi  $t3           # 读取高32位
```

无符号乘法使用：

```asm
multu $t0, $t1
```

有些环境允许：

```asm
mul $t2, $t0, $t1
```

这种写法通常只把低 32 位放进目标寄存器，高位结果不会作为普通目标寄存器返回。如果题目关心溢出或完整 64 位乘积，就不能只看 `mul` 的低位结果。

任何后续的乘法或除法都可能覆盖 `HI/LO`。如果当前结果之后还要使用，应该尽快用 `mfhi/mflo` 取出；如果还要跨过一次 `jal`，也不能假设被调用函数会替我保留它们。

### 2. 有符号乘法怎样判断是否装得下低半部分

对于无符号乘法，只要高半部分不是 0，就说明完整结果无法只用低 `n` 位表示。

有符号补码不能简单判断“高半部分是否为 0”。负数正常情况下高半部分应该全是 1。判断能否只用低半部分表示时，要看高半部分是否等于低半部分符号位的完整符号扩展：

```text
低半部分最高位为0：高半部分应全0
低半部分最高位为1：高半部分应全1
```

不满足时才是有符号结果超出 `n` 位范围。

### 3. 除法同时产生商和余数

Logisim 除法器通常直接给出两个结果：

```text
quotient：商
remainder：余数
```

MIPS 则把它们分别放进特殊寄存器：

```asm
div  $t0, $t1       # 有符号除法
mflo $t2            # $t2 = 商
mfhi $t3            # $t3 = 余数
```

无符号除法使用：

```asm
divu $t0, $t1
```

在递归 GCD 中：

```asm
div  $a0, $a1
move $a0, $a1
mfhi $a1
```

这里只关心余数，所以使用 `mfhi`。原来的 `b` 成为下一层的 `a`，余数成为下一层的 `b`。

有符号除法通常向 0 截断商，余数满足：

```text
被除数 = 商 * 除数 + 余数
```

除数为 0 时不能把输出当作正常结果。设计电路或写汇编前都应该单独拦截这个情况。

### 4. 加减法下面的输出不一定叫“有符号溢出”

Logisim 加法器下面常见的是 `carry in/carry out`：

```text
无符号加法：carry out为1，说明产生了最高位进位。
```

但有符号补码溢出不是简单看 carry out。有符号加法在“两个同号数相加却得到异号结果”时溢出：

```text
正数 + 正数得到负数
负数 + 负数得到正数
```

减法器的 `borrow out` 表示无符号借位或下溢，也不能直接当作有符号溢出标志。

所以以后看模块下面的额外端口，要先确认它到底是：

```text
carry、borrow、overflow、upper product还是remainder
```

它们都和“结果超出主输出”有关，但含义并不相同。

## 七、Logisim 小技巧：先分清方便与正确

### 1. Negator 是取相反数，不是逐位取反

Logisim 的 Negator 表示算术取负：

```text
output = -input
```

在 `n` 位补码中，它等价于：

```text
-x = (~x) + 1
```

而普通 NOT Gate 才是把每一个 bit 分别翻转。

以 8 位的 `1` 为例：

```text
输入1：       0000 0001
逐位NOT：    1111 1110   # 0xFE
Negator取负：1111 1111   # -1
```

二者只差一个加一，但含义完全不同。

还要注意补码最小值。例如 8 位补码的 `-128` 是 `1000 0000`，可表示范围中没有 `+128`，所以对它取相反数后位模式仍然是 `1000 0000`，这属于算术溢出。

### 2. MUX 上碍眼的 `en`

普通选择器只需要选择端和数据端时，可以在 MUX 属性中关闭 Enable 输入。这样 `en` 引脚会消失，电路图也更干净。

如果保留 `en`，就必须明确它在有效电平下 MUX 才输出正常结果。不能让它悬空，再期待选择器自己工作。

### 3. DMUX 的三态输出不是逻辑 `X`

DMUX 会把输入送到被选中的一路。开启 Three-state 后，未选中的输出通常进入高阻态 `Z`，含义是：

```text
这一端暂时不驱动总线。
```

`Z` 和未知值 `X` 不是同一个东西。只有当线路没有任何有效驱动、多个驱动发生冲突，或者未知控制信号参与运算时，后面才可能观察到 `X`。

更重要的是：**如果几个寄存器共用一个时钟，把未选中寄存器的 D 端变成 `Z/X`，并不能让寄存器自动保持旧值。** 到了时钟沿，它可能把未知状态采进去。

要实现“只写某个寄存器，其他寄存器保持不变”，更稳妥的方法是：

```text
方法一：分别控制每个寄存器的Enable，只给目标寄存器写使能。

方法二：每个寄存器前放MUX：
       需要写入时选择newValue；
       不写时选择自己的Q反馈，即D=Q。
```

三态输出适合共享总线，寄存器保持则应该依靠写使能或反馈 MUX。这两个用途不要混在一起。

### 4. `clk` 和 `reset` 靠得太近

寄存器的时钟端与复位端位置很接近，一根线稍微拐错就可能把它们接到同一网络。表现往往不是明显报错，而是寄存器不断清零、状态偶尔跳变，或者时钟一来整个结果就不对。

画图时可以故意做到：

- 时钟线统一从下方进入；
- reset 统一走另一条水平总线；
- 两条控制线之间至少留一个网格；
- 在关键线上放 Probe 或 Tunnel 标签；
- 放大检查交叉处到底有没有连接圆点。

## 八、寄存器时序：D 是准备值，Q 才是当前状态

这是今天 Logisim 部分最应该记住的地方。

寄存器不是在整个周期中不停把 D 复制到 Q，而是在有效时钟沿发生：

```text
时钟沿到来前：组合逻辑不断计算D
时钟沿到来时：寄存器采样D
时钟沿之后：Q更新，组合逻辑再根据新Q重新计算
```

所以不应说：

> D 端在 T1 周期结束之后写入了值，在这之前一直是 0。

更准确的是：

> T1 期间，D 端可能早已由组合逻辑算出新值；T1 结束处的有效时钟沿把当时的 D 采入寄存器，随后 Q 才变成这个新值。

真正被保存的是 Q，D 只是“下一状态输入”。

## 九、给寄存器赋初值为什么会花一个周期

如果我自己用 MUX 给寄存器实现初始化：

```text
第一次写入：D选择initial
以后写入：D选择nextState
```

那么初值也必须等到一次有效时钟沿才能进入 Q。可以用下面的记法，避免“第几个周期”说乱。

| 时段/时钟沿 | 发生的事 |
|---|---|
| 上电后、第一上升沿前 | Q 仍是模拟器初态；初始化 MUX 把 initial 放到 D |
| 第一个上升沿 E1 | 寄存器采样 initial |
| E1 之后，也就是 T1 期间 | Q 已经是初值；组合逻辑第一次根据正式初值计算 nextState |
| 第二个上升沿 E2 | 寄存器采样第一次计算出的 nextState |
| E2 之后 | Q 中第一次出现正式迭代结果 |

因此可以说：

```text
第一个周期用于准备并装载初值；
第一个上升沿之后开始正式组合计算；
第二个上升沿之后才看到第一轮计算状态写入寄存器。
```

与其只说“T0、T1”，更不容易混乱的方法是同时写清楚“第几个上升沿之前/之后”。因为有人把上电后的区间叫 T0，也有人把第一次上升沿后的区间叫 T0。

如果使用异步 reset/preset，初值可能不必等待正常计算时钟；但那是另一种初始化结构，不能和“通过 D 端同步装载初值”混为一谈。

## 十、自动售货机：状态到底代表什么

状态机不是先想“该画几个圆”，而是先写清楚这一拍的三样东西：

```text
CState：当前寄存器已经记住的历史
input：当前这一拍新来的输入
NState：处理完当前输入后，下一拍应该记住什么
```

所有有限状态机都有同一个状态转移式：

```text
NState = f(CState, input)
```

Moore 和 Mealy 的区别只在输出从哪里产生：

```text
Moore：output = g(CState)
Mealy：output = g(CState, input)
```

### 售价 5 元、串行投入 2 元或 3 元

“串行”表示每个周期最多处理一枚硬币。状态表示**处理当前硬币之前，机器已经累计了多少钱**。

#### Moore 状态机

Moore 的输出只能看 `CState`。因此要等状态真的进入“已付够钱”以后，才能出货：

```text
S0、S2、S3、S4：还没付够，数字是已累计金额
S5：出货，不找零
S6：出货，找零1元
S7：出货，找零2元
```

例如：

```text
CState=S2，input=3
组合逻辑算出 NState=S5
时钟沿后 CState=S5
因为 Moore output=g(CState)，此时才出货
下一拍再由 S5 回到 S0
```

所以 Moore 需要 `S5、S6、S7`。这些状态不只是“金额”，还承担了“把出货和找零保持一个周期”的任务。

#### Mealy 状态机

Mealy 可以同时看当前状态和当前硬币，所以在“这枚硬币让总额达到 5 元”的那条边上直接出货：

```text
S0、S2、S3、S4
```

通常不需要 `S5、S6、S7`，因为够钱时已经在转移边上输出，然后 `NState` 直接回到 `S0`。

| CState | input | NState | vend | change |
|---|---:|---|---:|---:|
| S0 | 2 | S2 | 0 | 0 |
| S0 | 3 | S3 | 0 | 0 |
| S2 | 2 | S4 | 0 | 0 |
| S2 | 3 | S0 | 1 | 0 |
| S3 | 2 | S0 | 1 | 0 |
| S3 | 3 | S0 | 1 | 1 |
| S4 | 2 | S0 | 1 | 1 |
| S4 | 3 | S0 | 1 | 2 |

如果还有“本周期没有投币”，可以令 `input=0`，使 `NState=CState` 且不输出。

### 初始化与第一个正式周期

我的说法可以整理成下面这条时间线。假设使用 MUX 从 D 端**同步装入**初始状态 `S0`：

| 阶段 | CState/Q | 组合逻辑在做什么 | 周期末时钟沿 |
|---|---|---|---|
| 第 0 周期 | 还不是可信的正式状态 | `init=1`，把 `S0` 放到 D | 把 `S0` 写进状态寄存器 |
| 第 1 周期 | `CState=S0` | 用 `S0 + input1` 算 `NState`；Mealy 同时算 output | 把 `NState` 写入寄存器 |
| 第 2 周期 | `CState=上一拍的 NState` | 处理 `input2` | 再写入新的 `NState` |

因此这句话只需要补上 Moore/Mealy 的区别：

> 第 0 周期结束的时钟沿完成同步初始化；第 1 周期才拿正式的 `CState=S0` 和第一个输入计算 `NState`。Mealy 的输出也由这两者计算，而 Moore 的输出只由 `CState` 计算。

在 Logisim 中可以直接分成三块画：

```text
状态寄存器：保存 CState
下一状态组合逻辑：CState + input -> NState
输出组合逻辑：Moore 只接 CState；Mealy 接 CState + input
```

不要把 `NState` 当作当前状态去算输出。`NState` 只是准备放在 D 端、等待下一个时钟沿写入的值。若 Moore 需要根据“新状态”输出，应该等时钟沿后它成为 `CState`。

## 十一、矩阵快速幂电路：画线之前先写状态转移

矩阵快速幂至少需要三个状态：

```text
R：当前答案矩阵
B：当前底数矩阵
N：当前指数
```

以斐波那契转移矩阵为例，初始化通常是：

```text
R = 单位矩阵I
B = 斐波那契基础矩阵
N = 输入指数
```

每一轮根据旧状态计算：

```text
如果N最低位为1：nextR = R * B
否则：          nextR = R

nextB = B * B
nextN = N >> 1
```

然后在同一个有效时钟沿：

```text
R <- nextR
B <- nextB
N <- nextN
```

这里所有 next 值都必须由时钟沿之前的旧 `R、B、N` 计算。不能误以为同一个上升沿里先写了 `R`，再拿更新后的 `R` 去算 `B`。寄存器是同时采样的。

### 建议先写周期表

假设第一拍专门初始化，可以先写：

| 阶段 | Q 中保存的状态 | 组合逻辑正在计算 | 下一个沿写入什么 |
|---|---|---|---|
| 初始化沿之前 | 模拟器初态 | initial | `R=I, B=Base, N=input` |
| 初始化沿之后 | 正式初值 | 第一轮 `nextR,nextB,nextN` | 第一轮结果 |
| 第二个沿之后 | 第一轮结果 | 第二轮 next 状态 | 第二轮结果 |
| `N=0` | 最终状态 | 不再继续迭代 | 保持结果并置 done |

我以后调试时不应该只看“现在屏幕上的数字像不像”，而要逐周期写：

```text
这个周期开始时，Q 是什么？
这个周期中，D 被组合逻辑算成什么？
这个周期结束的上升沿后，Q 应该变成什么？
```

如果对不上，再沿着 `Q → 组合逻辑 → D → 时钟沿 → Q` 查，而不是在整个电路里到处猜。

## 十二、矩阵快速幂画图前的规划清单

在 Logisim 里直接开始拖元件，很容易画到一半才发现控制信号和数据通路互相打架。下一次应该先回答：

```text
1. 哪些是状态寄存器？R、B、N，还需要init/done吗？

2. 每个寄存器的初值是什么？通过同步MUX装载，还是reset实现？

3. 每个寄存器的next表达式是什么？

4. 哪些运算可以在同一周期并行？

5. 哪一个上升沿装载初值？哪一个上升沿写入第一轮结果？

6. N=0时，寄存器保持还是继续写？done什么时候有效？

7. 输出取R的哪个矩阵元素？读取时是否已经done？

8. 所有数据位宽是否一致？乘法与累加是否会溢出？

9. clk、reset、enable有没有悬空、误接或被连成同一网络？
```

先把这些内容写成表，再画数据通路，最后才连接控制线。这样电路不是“凭感觉能跑”，而是每根线都对应一条已经写清楚的状态转移。

## 今天留下来的两句话

MIPS 递归中：

> 当前层只保存自己跨过 `jal` 后还需要的值；子调用返回时，相信结果已经按约定放在 `$v0`。

Logisim 时序中：

> 一个周期里组合逻辑负责准备 D，时钟沿负责把 D 采入 Q；分析电路要盯着每个沿前后的状态，而不是只盯着某一刻的数字。

这两句话其实都在提醒我：不要一次展开所有递归层，也不要一次想完整条时间线。先把当前层、当前周期的输入、保存内容和输出说清楚，复杂结构才不会失控。
