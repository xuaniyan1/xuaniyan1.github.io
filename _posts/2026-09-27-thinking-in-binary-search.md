最近连续写了几道二分题之后，我发现自己很容易进入一种状态：看见题目像二分，就先写出 `l、r、mid、ans`，然后再想办法把题意塞进 `check(mid)`。简单题有时能过，但题目稍微变化，我就会开始纠结：`r` 到底该多大，`check` 返回什么，`ans` 为什么要初始化成这个数，以及可行以后究竟该往左还是往右。

这不是二分模板背得不熟，恰恰是模板已经盖住了问题本身。

这篇笔记不准备再收集几份只有边界符号不同的代码。我要弄清楚的是：**我到底在什么集合上搜索，真假为什么单调，边界凭什么包含答案，循环中的每一次更新又保留了什么事实。**

---

## 一、先分清两件长得很像的事

### 1. 在有序数组中二分下标

这种问题已经有一组排好序的数据，我搜索的是下标：

```text
0, 1, 2, ..., n-1
```

例如寻找数组中第一个大于等于 `x` 的位置。定义：

```text
P(i)：a[i] >= x
```

因为数组递增，`P(i)` 的排列一定是：

```text
F F F F T T T
        ↑
    第一个 true
```

这里的 `l、r` 是**下标**。有效数据只有 `a[0]` 到 `a[n-1]`，所以闭区间写法的右边界只能是 `n-1`。把 `r` 写成一个很大的数并不会更保险，反而会把没有输入的数组位置也放进搜索区间。

全局数组后半部分虽然会自动初始化为 `0`，但原本的：

```text
1 3 5
```

会在错误的搜索范围里变成：

```text
1 3 5 0 0 0 ...
```

条件 `a[i] >= x` 不再保持单调，二分的前提已经消失。正确做法不是把后面的元素填成无穷大，而是根本不搜索它们。

### 2. 在可能答案中二分

答案二分没有现成的有序数组。我们搜索的是速度、时间、距离、天数、重量标准等答案值：

```text
候选答案 x
    ↓
固定 x 后判断是否满足要求
    ↓
利用判断结果的单调性排除一半候选答案
```

例如“最少生产多少天”，搜索的是天数；“最大化牛之间的最小距离”，搜索的是距离。这时 `l、r` 必须来自答案本身可能取得的范围，不能再机械地写成 `0` 和 `n-1`。

两类二分使用的循环可能一模一样，但搜索对象完全不同：

| 类型 | 搜索对象 | 边界来自哪里 |
|---|---|---|
| 下标二分 | 有序数组中的位置 | 实际有效下标范围 |
| 答案二分 | 时间、速度、距离等答案值 | 对答案上下界的证明 |

## 二、二分搜索的不是公式，而是真假分界

我以前容易把 `check(x)` 理解成“代入 `x` 算一下”。这还不够。一个能够用于二分的 `check(x)`，必须回答一句固定的是非问题，并满足两个要求：

1. 相同的 `x` 调用多少次，结果都相同；
2. 随着 `x` 增大，返回值最多只改变一次。

常见形状只有两类。

### 找第一个可行值

```text
F F F F T T T
        ↑
    第一个 true
```

常见题目：最小速度、最少天数、最早时间、第 `k` 小的值。

当 `check(mid)` 为真时，`mid` 已经可行，但可能还有更小的可行值，所以继续搜索左边；为假时只能去右边。

### 找最后一个可行值

```text
T T T T F F F
      ↑
  最后一个 true
```

常见题目：最大距离、最长运行时间、最大容量。

当 `check(mid)` 为真时，`mid` 可行，但可能还能继续增大，所以去右边；为假时说明太激进，只能回到左边。

### 一个不能用于二分的 `check`

我在“聪明的质监员”中曾经让 `check(x)` 返回：

```text
当前差值是否刷新了历史最小差值？
```

这不是关于 `x` 的固定性质，而是依赖之前搜索过哪些位置。同一个 `x` 第一次调用可能刷新答案并返回真，第二次调用却不再刷新并返回假。这样的结果不会形成稳定的真假分界，当然不能决定二分方向。

所以需要把三件事分开：

```text
calculate(x)：计算候选 x 对应的量
predicate(x)：提供单调的是非判断
best：记录目前见到的最优目标值
```

## 我真正想固定下来的思考顺序

我之前一直在找一个“通用的 `check` 模板”，但现在觉得这个目标本身就有点偏。真正通用的并不是一定要写出一个叫 `check` 的布尔函数，而是下面这句话：

> 先把 `mid` 当成已经确定的事实。暂时不求最优答案，只问：在这个事实之下，我能算出什么，又能据此排除哪一边？

我可以固定使用下面这条思路。

### 第一步：把题目最终要求的量圈出来

先写一句：

```text
x 表示 ______。
```

多数题并不难确定二分什么。题目问最短等待时间，`x` 就是时间；问最大牛间距离，`x` 就是距离；问怪兽最少第几回合死亡，`x` 就是死亡回合。这里不必故意寻找隐藏变量。

第 `k` 小一类题稍微绕一点。它虽然要求一个排序位置，但 `x` 仍然取“可能的答案值”，然后统计不超过 `x` 的元素有多少个。

### 第二步：假装 `x` 已经由别人告诉我了

这是最重要的一步。原题还在问“最少”“最大”时，我同时面对许多候选答案，很容易乱。现在先不优化，只处理一个具体问题：

```text
如果答案限制为 x，会发生什么？
```

固定以后，不同题消失的不确定性不同：

- 固定香蕉速度后，只需计算总用时；
- 固定牛间距离后，只需贪心试放一次；
- 固定等待时间后，只需统计已经产生多少服务位置；
- 固定第 `k` 小距离的候选值后，只需统计距离不超过它的数对；
- 固定怪兽的死亡回合后，毒还能生效多少回合也被确定了。

所以“固定 `x`”不是一句空话。它的作用是把原题中的一个全局不确定量钉死，让剩下的问题变成一次计算、一次贪心或一次计数。

### 第三步：先写 `evaluate(x)`，不强求它立刻是 bool

固定 `x` 后，我实际算出的东西可能不同：

```text
香蕉：需要多少小时
排队：已经产生多少服务位置
放牛：最多能放多少头牛
质检员：当前检验值 y(W)
毒杀怪兽：在第 T 回合前最多能造成多少伤害
数组查找：a[mid] 与目标值的大小关系
```

可以先把它统称为 `evaluate(x)`。有时它直接返回 `true/false`，有时返回一个数量。等这个量算清楚以后，再把它和题目要求比较：

```text
hours(x) <= h
served(x) >= m+1
cows(x) >= m
damage(x) >= hp
y(W) >= s
a[mid] >= target
```

这些比较才形成二分真正需要的谓词。代码里不一定非要出现一个名叫 `check` 的函数；判断可以直接写在循环中，但逻辑上的这句话必须存在。

### 第四步：问“把 x 增大，刚才那个结论会怎样”

不要直接背 `l=mid+1`。先用人话判断趋势：

```text
香蕉速度增大，总用时只会减少，因此更容易完成。
牛间距离增大，能放下的牛只会减少，因此更难完成。
等待时间增大，出现的服务位置只会增加，因此更容易轮到我。
重量标准增大，入选矿石只会减少，因此检验值只会下降。
```

说清这句话以后，真假排列和更新方向自然就出来了。

### 第五步：不是问“mid 对不对”，而是问“哪一边已经不可能”

例如放牛时，`mid` 可行并不代表它就是答案；它只证明所有更小距离也可行，因此我要保留 `mid` 和右边，继续挑战更大距离。

质检员中，如果 `y(mid)>s`，也不是说 `mid` 是错答案，而是说为了让 `y` 下降，只可能增大重量标准，所以较小的一边可以排除。

二分每一步真正做的是证明一半范围不可能包含更优答案，而不是猜中当前 `mid`。

### 第六步：最后才写边界和循环

到这里我已经知道：搜索的量、固定以后怎么算、比较条件、单调方向和要保留哪一边。此时才去证明 `l、r`，然后选择熟悉的闭区间或哨兵写法。

如果第二步固定 `x` 后仍然和原题一样难，或者第四步发现真假会来回变化，那么这题大概率不能这样二分。这个判断比强行套出一个 `check` 更有用。

### 刀砍与下毒为什么特别能说明这条思路

这道题直接思考每回合选刀还是毒，会觉得前后纠缠：毒的收益取决于战斗还会持续多少回合，而战斗持续多久又取决于前面选了多少毒。

先固定死亡回合 `T`，这个环就断开了。第 `i` 回合选择刀，贡献是 `cuts[i]`；选择毒，截至第 `T` 回合的贡献是“单回合毒伤乘以剩余生效回合数”。两种选择的收益都已经是确定数字，于是这一回合直接取较大者。把每回合的最大贡献加起来，就能判断第 `T` 回合前能否造成至少 `hp` 点伤害。

这里固定 `T` 同时解决了两个问题：它告诉我应该二分什么，也让原本互相依赖的选择变得可以独立计算。

但不是每道题都这么戏剧化。香蕉题里二分速度本来就很明显，固定速度只是让“最小速度”变成一次总时间计算；数组下标二分甚至不需要单独写 `check`。它们共同的地方不是函数名字，而是：**固定当前候选以后，我得到一个有单调方向的比较结果，因此能安全地扔掉一半范围。**

## 三、为什么经常不是寻找等式，而是寻找不等式边界

假设两个服务员服务一个人分别需要 `2` 分钟和 `3` 分钟。到时间 `t` 为止，完成的服务次数为：

```text
t       0 1 2 3 4 5 6
次数    0 0 1 2 3 3 5
```

计数可能直接从 `3` 跳到 `5`，不一定存在“恰好服务了 4 人”的时刻。如果我要等第 4 个空位，寻找：

```text
count(t) == 4
```

可能永远找不到；真正的目标是：

```text
最小的 t，使 count(t) >= 4
```

因此二分答案经常是在求：

$$
\min\{x\mid f(x)\ge K\}
$$

或者：

$$
\max\{x\mid f(x)\text{ 仍然可行}\}
$$

这不是把题目强行改成不等式，而是离散计数本来就会跳跃。二分寻找的是跨过目标的边界，不要求函数值刚好等于目标。

## 四、右边界 `r` 不是猜出来的，而是证明出来的

我之前总想把 `r` 写得特别大，觉得“反正包含答案就行”。这在数学上不一定错，但很容易带来越界、溢出，也说明我并不知道答案为什么在这个范围内。

`r` 不必很紧，却必须能说出理由。

### 1. 求最小答案：构造一个一定成功的方案

如果问题求最少时间、最小速度或最少天数，我要证明：

> 当答案取到 `r` 时，任务一定已经能够完成。

例如排队问题中，即使忽略其他服务员，只让最快的服务员工作，经过 `m * minTime` 也一定能够轮到第 `m+1` 个人。因此真实的最短等待时间不会更长。

这类上界经常来自一个“很笨但一定能做完”的方案。它不需要最优，只需要可靠。

### 2. 求最大答案：找到绝对无法突破的资源限制

如果问题求最大距离或最长时间，我要证明：

> 答案一旦超过 `r`，一定不可能实现。

例如所有牛舍都位于最左位置和最右位置之间，任意两头牛的距离都不可能超过整个跨度。因此最大化最小距离时，可以把总跨度作为上界。

### 3. 找到“结果不再变化”的位置

在质检员问题中，只要 `W > max(w[i])`，就不会选中任何矿石，检验值永远为 `0`。继续增大 `W` 没有任何新结果，因此只需要搜索到：

```text
maxWeight + 1
```

### 4. 由总资源守恒得到上界

如果 `n` 台电脑同时运行 `T` 分钟，需要至少 `nT` 单位电量。总电量为 `E`，那么必有：

$$
T\le\left\lfloor\frac{E}{n}\right\rfloor
$$

### 5. 实在无法直接得到上界时使用倍增

对于“找最小可行值”的问题，可以从 `r=1` 开始不断翻倍，直到 `check(r)` 为真，再在得到的范围内二分。倍增不是放弃证明：第一次变为真的 `r` 本身就是通过 `check` 验证过的可行上界。

### 设置边界时不要提前解决整道题

放牛问题里，我曾经想到两头牛之间的最大距离，又立刻开始纠结剩下的 `m-2` 头怎么放，于是把边界和可行性混在了一起。

实际上：

- `r` 只负责提供一个天花板；
- `check(x)` 才负责判断在距离 `x` 下能不能放完 `m` 头牛。

最容易分开的两头牛尚且不可能超过整个跨度，增加更多牛以后最小距离只会变小。因此整个跨度已经是合法上界，到这里就应该停止边界推导。

## 五、`ans` 和 `res` 不是二分仪式，它们必须有语义

变量叫 `ans` 还是 `res` 并不重要，重要的是它究竟记录什么。

### 1. 记录目前找到的边界候选

寻找第一个可行值时，`ans` 可以表示：

```text
目前见过的最小可行值
```

初始化为 `-1` 表示尚未找到。如果每次 `check(mid)` 为真就记录 `mid` 并向左搜索，循环结束后它就是第一个可行值。

### 2. 记录目标函数的最优值

质检员中的 `minDifference` 表示：

```text
目前见过的最小 |y(W)-s|
```

它不是 `W`，也不决定二分方向。它应该使用一个已知合法方案初始化。因为取 `W=maxWeight+1` 时 `y=0`，已经得到差值 `s`，所以：

```text
minDifference = s
```

比随手写一个 `2e12+5` 更有意义。

### 3. 有时根本不需要 `ans`

如果维护“左端一定不可行、右端一定可行”的哨兵，最后右端就是第一个可行值；反过来维护“左端一定可行、右端一定不可行”，最后左端就是最后一个可行值。

所以 `ans` 不是每道二分题都必须出现的零件。只有当我能用一句话说清它记录什么时，才应该保留它。

“反正进入循环以后会更新”并不是可靠的初始化理由：循环可能一次都不执行，也可能记录答案的分支一次都没有进入。

## 六、题目一：在有序数组中寻找第一个指定值

### 题目描述

给定一个非递减整数数组 `a` 和一个目标值 `k`，输出 `k` 第一次出现的下标；如果不存在，输出 `-1`。

### 输入格式

第一行输入两个整数 `n,k`。第二行输入 `n` 个非递减整数。

```text
5 2
1 2 2 2 5
```

### 输出格式

输出 `k` 第一次出现的零基下标。

```text
1
```

### 数据范围（本文练习约定）

```text
1 <= n <= 2*10^5
-10^9 <= a[i], k <= 10^9
a[i] <= a[i+1]
```

### 思维分析

搜索对象是下标 `i`，定义：

```text
P(i)：a[i] >= k
```

它一定呈现 `F...FT...T`。先找到第一个 `P(i)=true` 的位置，再检查这个位置是否真的满足 `a[i]==k`。如果第一个大于等于 `k` 的元素已经大于 `k`，说明数组中不存在 `k`。

右边界来自有效数组下标，而不是数据值大小：闭区间是 `n-1`，左闭右开区间可以写成 `n`，但此时 `n` 只是一个永远不会被访问的尾后位置。

## 七、题目二：猴子吃香蕉

### 题目描述

有 `n` 堆香蕉，第 `i` 堆有 `piles[i]` 根。猴子每小时选择一堆，最多吃 `k` 根；如果这一堆不足 `k` 根就全部吃完。求在 `h` 小时内吃完全部香蕉的最小整数速度 `k`。

### 输入格式（本文练习版）

第一行输入 `n,h`，第二行输入 `n` 个整数 `piles[i]`。

```text
4 8
3 6 7 11
```

### 输出格式

输出最小速度。

```text
4
```

### 数据范围（常见版本）

```text
1 <= n <= 10^4
n <= h <= 10^9
1 <= piles[i] <= 10^9
```

### `check(k)` 回答什么

固定速度 `k` 后，总用时为：

$$
\sum_i\left\lceil\frac{piles_i}{k}\right\rceil
$$

`check(k)` 表示能否在 `h` 小时内吃完，即总用时是否不超过 `h`。

速度越大越容易完成，所以真假序列是：

```text
F F F T T T
```

目标是第一个 `true`。

### 为什么 `r=max(piles)`

速度等于最大一堆时，每一堆最多只需一小时。题目保证 `h>=n`，所以这个速度一定可行。继续提高速度也不可能把“一堆至少占用一小时”缩短成零小时。

## 八、题目三：并行生产糖果

### 题目描述

工厂可以并行生产 `n` 种糖果，第 `i` 种每天生产 `arr[i]` 个。订单需要至少 `a` 包糖果，每包必须由同一种糖果组成且至少含有 `b` 个；一种糖果可以组成多包。求完成订单至少需要多少天。

### 输入格式（本文练习版）

第一行输入 `n,a,b`，第二行输入 `n` 个日产量。

```text
3 8 5
4 7 10
```

### 输出格式

输出最少天数。

```text
3
```

### 数据范围（本文练习约定）

```text
1 <= n <= 2*10^5
1 <= a,b,arr[i] <= 10^9
```

### `check(days)` 回答什么

第 `i` 种糖果生产 `days` 天后可以组成：

$$
\left\lfloor\frac{arr_i\times days}{b}\right\rfloor
$$

包。`check(days)` 表示所有种类合计能否组成至少 `a` 包。

天数越多越容易完成，因此寻找第一个 `true`。

### 如何构造右边界

只保留日产量最高的一种糖果，忽略所有其他种类。只靠它生产出 `a*b` 个糖果所需的天数一定足够；真实情况下其他种类还会并行生产，只可能更快。这个“故意忽略帮助”的方案给出了可靠上界。乘法必须注意溢出。

## 九、题目四：计算等待时间

### 题目描述

有 `n` 个服务员，第 `i` 个服务员服务一个人需要 `arr[i]` 分钟。开始时所有服务员空闲，前面已有 `m` 个人等待，我是刚到的第 `m+1` 个人。求至少等待多少分钟才能开始接受服务。

### 输入格式（本文练习版）

第一行输入 `n,m`，第二行输入每个服务员的服务时间。

```text
2 4
2 3
```

### 输出格式

输出最短等待时间。

```text
4
```

### 数据范围（课程截图中可见部分）

```text
n <= 10^3
m <= 10^9
arr[i] 为正整数
```

### `check(time)` 回答什么

因为服务员在时间 `0` 就能接待第一个人，第 `i` 个服务员截至 `time` 时能够开始接待：

$$
\left\lfloor\frac{time}{arr_i}\right\rfloor+1
$$

个人。`check(time)` 表示这些位置总数是否至少为 `m+1`。

如果另一道题规定时间 `0` 时服务员已经在忙，那么这里就不能加 `1`。公式不是模板的一部分，它来自时间模型。

### 为什么右边界可以是 `m*min(arr)`

即使只让最快的服务员工作，他也会在 `0,minTime,2*minTime,...,m*minTime` 接待 `m+1` 个人。其他服务员的存在只会缩短等待时间。

## 十、题目五：最大化牛之间的最小距离

### 题目描述

一条直线上有 `n` 间牛舍，第 `i` 间位于 `x[i]`。需要选择其中 `m` 间放置 `m` 头牛，使任意两头牛之间的最小距离尽可能大，输出这个最大值。

### 输入格式

第一行输入 `n,m`，随后输入 `n` 个牛舍位置。

```text
5 3
1 2 4 8 9
```

### 输出格式

输出最大化后的最小距离。

```text
3
```

### 数据范围（本文练习约定）

```text
2 <= m <= n <= 2*10^5
0 <= x[i] <= 10^18
```

### `check(distance)` 回答什么

固定最小距离 `distance`，将牛舍排序，从最左牛舍开始放第一头牛，之后每次选择距离上一头牛至少为 `distance` 的最靠左牛舍。这样会给后面的牛留下尽可能大的空间。

`check(distance)` 表示这个贪心过程能否放下至少 `m` 头牛。

距离越大越难放，因此真假序列是：

```text
T T T T F F F
```

目标是最后一个 `true`。

### 为什么可以暂时不管 `m` 来设置 `r`

所有牛都必须位于最左和最右牛舍之间，任何两头牛的距离都不可能超过：

```text
maxPosition - minPosition
```

两头牛是最容易分开的情况；增加更多牛只会让最小距离更小。所以整个跨度已经是所有 `m>=2` 情况的统一上界。设置 `r` 时不必同时解决怎样放完 `m` 头牛，那是 `check` 的职责。

如果追求更紧的上界，`m` 头牛之间有 `m-1` 个间隔，因此最小距离不超过 `span/(m-1)`。但更紧不是正确性的必要条件。

## 十一、题目六：第 k 小的数对距离

### 题目描述

给定整数数组 `nums`，数对 `(nums[i],nums[j])` 的距离为绝对差，求全部 `i<j` 数对中第 `k` 小的距离。

### 输入格式（本文练习版）

第一行输入 `n,k`，第二行输入数组。

```text
3 1
1 3 1
```

### 输出格式

输出第 `k` 小的数对距离。

```text
0
```

### 数据范围（常见版本）

```text
2 <= n <= 10^4
0 <= nums[i] <= 10^6
1 <= k <= n*(n-1)/2
```

### `check(distance)` 回答什么

将数组排序后，统计距离不超过 `distance` 的数对数量 `count(distance)`。可以用双指针在线性时间内完成计数。

定义：

```text
check(distance)：count(distance) >= k
```

如果成立，第 `k` 小距离一定不超过当前候选；如果不成立，说明候选值太小。目标是第一个 `true`。

右边界是数组最大值与最小值之差，因为任何数对距离都不会超过它。

## 十二、题目七：P1314 聪明的质监员

### 题目描述

有 `n` 个矿石，第 `i` 个矿石有重量 `w[i]` 和价值 `v[i]`。给定 `m` 个区间和标准值 `s`。选择整数参数 `W`，对每个区间统计重量不小于 `W` 的矿石数量与价值总和，并将两者乘积作为区间检验值。所有区间检验值之和为 `y(W)`，要求最小化：

$$
|s-y(W)|
$$

### 输入格式

第一行输入 `n,m,s`；接下来 `n` 行输入 `w[i],v[i]`；再接下来 `m` 行输入区间 `l[i],r[i]`。

### 输出格式

输出最小的绝对差。

样例输入：

```text
5 3 15
1 5
2 5
3 5
4 5
5 5
1 5
2 4
3 3
```

样例输出：

```text
10
```

### 数据范围

```text
1 <= n,m <= 2*10^5
0 < w[i],v[i] <= 10^6
0 < s <= 10^12
1 <= l[i] <= r[i] <= n
```

### 固定 `W` 后如何计算

建立两个前缀和：

```text
countPrefix[i]：前 i 个矿石中 w[j]>=W 的数量
valuePrefix[i]：前 i 个矿石中 w[j]>=W 的价值和
```

每个区间便能在 `O(1)` 时间得到数量和价值和，一次计算 `y(W)` 的总复杂度为 `O(n+m)`。不能在每个区间里重新扫描矿石，否则最坏复杂度会达到 `O(nm)`。

### 单调性与更新方向

`W` 增大时，满足条件的矿石只会减少，所以 `y(W)` 单调不增。

```text
如果 y(W)>s：结果太大，需要增大 W，让 y 下降
如果 y(W)<s：结果太小，需要减小 W，让 y 上升
```

与此同时，用当前的 `|y(W)-s|` 更新最小差值。更新最小差值和决定搜索方向是两件事。

### 为什么搜索到 `maxWeight+1`

当 `W=maxWeight+1` 时，没有矿石入选，`y(W)=0`；更大的 `W` 仍然得到相同结果。因此 `[0,maxWeight+1]` 已经覆盖了所有不同状态。

### 这道题不是最标准的“找一个可行答案”

它最终要求的是最小绝对差，而不是分界点本身。但由于 `y(W)` 单调下降，`|y(W)-s|` 的最优位置必然出现在 `y(W)` 跨过 `s` 的附近。二分负责找到这个交界，最小差值变量负责比较交界两侧。

进一步看，`y(W)` 只会在 `W` 跨过某个矿石重量时改变，所以还可以将所有重量排序去重，在这些离散候选附近搜索。数值二分不是唯一理解方式。

理论上所有区间结果累加可能超过 `long long`，稳妥实现可以在计算 `y` 时使用 `__int128`；最终最小差值不会超过取 `W=maxWeight+1` 时得到的 `s`。

## 十三、一次二分前应该完成的草稿

以后不急着写循环，先填完下面这些句子：

```text
1. 我搜索的 x 是下标，还是答案值？

2. check(x) 完整地说是什么意思？

3. x 增大时，check 是：
   F F F T T T
   还是
   T T T F F F？

4. 我要找第一个 true，还是最后一个 true？

5. 左边界为什么不会漏掉答案？

6. 右边界为什么一定覆盖答案？
   是构造了必定成功的方案，还是找到了不可突破的限制？

7. ans/res 记录的到底是候选参数，还是目标函数值？

8. check 是否只依赖 x？同一个 x 调用两次会不会得到不同结果？

9. 固定 x 后的计算是否足够快？二分外层的对数复杂度不能挽救 O(nm) 的 check。

10. 中间量会不会溢出？边界加一、乘法和累计和尤其需要检查。
```

如果这些问题还没有答案，先写二分模板通常只是在把困惑藏进变量名里。

## 十四、反过来审查这套理解

### “有单调函数”还不够

真正需要的是能够快速计算的单调谓词。有些量虽然单调，但一次判断和暴力解原题一样慢，套上二分仍然无法通过。质检员需要前缀和，第 `k` 小数对距离需要排序与双指针，优化 `check` 本身也是题目的一部分。

### 右边界大并不自动错误，但必须安全

一个更大的合法上界通常只增加少量二分次数；问题在于无证明的“大数”可能仍然不够大，也可能造成乘法、`mid+1` 或数组访问溢出。边界的价值首先是正确性证明，其次才是效率。

### 并不是所有目标函数都能二分

“我能计算 `f(x)`”不代表可以二分。必须证明某个判断只发生一次真假切换。一般的先变小后变大函数、带多个峰谷的函数，不能直接按照 `check(mid)` 的真假丢掉一半范围。

### `check` 最好保持纯粹

为了调试和证明，`check(x)` 最好只回答固定问题，不悄悄修改全局最优值。像质检员这种需要同时计算数值与更新答案的题，可以让 `calculate(x)` 返回 `y`，在二分函数中分别处理“更新最优值”和“移动边界”。

### 模板仍然有价值

不套模板不等于每次重新发明循环。循环、`mid` 防溢出写法和两类边界搜索完全可以固定。真正不能模板化的是：`x` 的意义、单调性的证明、`check` 的实现与边界的来源。

我现在更愿意把二分理解成一句话：

> 先把优化问题改写成关于候选答案的判定问题，再用一个有证明的搜索区间，寻找单调真假序列的分界。

模板只是最后把这句话翻译成代码。
